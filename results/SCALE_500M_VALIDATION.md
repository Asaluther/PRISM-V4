# 500M 判决实验（W1/B4 终点）：压缩曲线反转

> 日期：2026-09-21 深夜 | 平台：启智 V100S-32GB × 2 任务（~39.3 积分，余额恰好用尽）
> 脚本：`run_openi.py` v3.5（m500_hyb / m500_tf）| 数据：本地固化
> `results/wt_516m_hyb_ng_lr5e-4_s0/` 与 `results/wt_553m_tf_lr5e-4_s0/`
> 协议：与 330M 点（run_d1024_reinforce.sh）逐字段一致，仅 d_model 1280 /
> n_heads 10 / ffn 5120 升档。164M tokens ≈ 328-497 t/p。

## 一、终表

| | HYB 12+12（499.5M） | TF 24L（536.9M） |
|---|---|---|
| lr（直承） | 骨干 5e-4 / 头 1e-4 | 5e-4 |
| **Best PPL** | **39.55** | **750.35** |
| 轨迹 | 单调健康改善到底 | 2K 步早期最优 1024.51 → 5e-4 平台期劣化至 1182 → cosine 衰减后爬回 750 |
| 训练事件 | ~700 次 fp16 孤立跳过 + 1 次紧急回滚（10425 步 lr×0.5，自愈） | **零 NaN**——纯优化动力学失效 |
| 用时 / VRAM | 190.8min / 22.2GB | 202.6min / 19.5GB |

**同协议优势 = 1 − 39.55 / 750.35 = 94.7%。**

## 二、判决：压缩曲线反转，而非归零

直承口径（双方沿用各自 330M 最优）的跨规模曲线：

| 规模 | tokens/param | HYB vs TF 优势 |
|---|---|---|
| 96M | 853 | **+36.4%** |
| 330M | ~470 | +5.3/+6.5/+35.5%（配对；TF σ 爆炸 11.67） |
| **500M** | ~328 | **+94.7%** |

B4 解耦实验曾给出「规模压缩 -47pp 主导」的担忧：优势将在更大规模归零。
**500M 实测否定了归零方向**——越过 TF 的甜点区（330M 档）后，TF 在深稀缺区
过热塌方，优势反转扩大。中段收窄是 TF 的最优区间，不是趋势终点。

## 三、两种天花板的对照（本实验的核心叙事）

330M → 500M（同 164M tokens 预算）：

- **HYB 撞饱和墙**：39.75 → 39.55（零增益、零损失——数据预算决定了混合架构
  的最优规模在 330-500M 之间）
- **TF 撞灾难墙**：41.72 → 750.35（**17.9×** 劣化）

数据稀缺前沿上：**混合架构的规模天花板是优雅的，纯 TF 的天花板是灾难性的**。

## 四、机制解读

1. TF 的塌方**零 NaN**——不是数值问题，是「536M 数据饥渴架构 @ 328 t/p
   深稀缺 + 为 354M 调好的步长」的优化动力学失效。这是 63M→101M 时纯 PCN
   崩溃（§4.6）的**镜像故事**：角色互换，教训对称——没有哪种架构在全部
   （规模 × 数据比）象限免于失稳，但混合架构在已测的三个点全程稳
2. B4 数据比规律的极端兑现：固定预算下扩大规模 = 深挖稀缺 → 稀缺放大
   混合优势（96M 点 +22pp 的规律在 500M 以 +83pp 量级再现）
3. HYB 的 fp16 边缘骑行（~700 跳过 + 1 回滚）再次被恢复机制自愈——
   「不稳定但可自愈」vs TF「干净地失败」的对照本身是恢复机制的价值证明

## 五、诚实边界

- **TF@2.5e-4 夹逼臂因积分不足被砍**——理论上 TF 在中低 lr 窗口可部分恢复。
  挤压论证：354M 时 2.5e-4 已大劣 52%（63.52 vs 41.72）、5e-4 在 500M 发散、
  TF 最优 lr 随规模下行——可用窗口即使存在也窄。判决按「直承口径 + 挤压
  论证」表述，无夹逼如实注明；积分恢复后 TF@2.5e-4 是第一优先补强项
- 双臂各单 seed；HYB 39.55 为「5e-4 含一次紧急降档」口径（干净跑估 ~38-39）
- 20K 步未饱和；HYB 的饱和墙结论限于 164M tokens 预算（更多数据会移动墙位）
