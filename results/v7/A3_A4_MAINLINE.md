## A3：int4 底座 + fp 适应头——**不需要了（正面修正）**

### 结果

| 臂 | before → after | 改善 | 恢复率 |
|---|---|---|---|
| A 全 fp32 | 1740 → 212 | +87.8% | — |
| **B 全 int4 fake-quant** | 1769 → 218 | **+87.7%** | **99.9%** |
| C int4 骨干 + fp 头 | 1772 → 210 | +88.2% | 100.4% |

### 关键发现：v7_demo 的「int4 适应损失 10pp」是 tokenizer 往返伪影

v7_demo 报告全 int4 适应 +59.8% vs fp32 +70.1%（差 10pp）。本实验用**同
一检查点、同一测试集、同一 50 步协议**但直接用 token ID（跳过 decode→
re-encode 往返），int4 适应完全不损失。

**根因**：v7_demo 的 `adapt()` 先将 token 解码为文本再重新编码——这个
往返引入了 tokenizer 的不一致性（特殊 token 处理/空格合并等），才导致了
适应增益差异。量化本身与适应完全兼容。

### 部署含义修正

- ~~两段式（int4 底座 + fp 头）是必要的~~ → **全 int4 即可直接适应**
- 体积最优解就是全 int4（132 MB vs 两段式 339 MB vs fp32 366 MB）
- 两段式仍有价值：如果未来用真 packed int4 kernel（非 fake-quant），
  packed 权重上做梯度更新可能需要 fp 适配头——但 fake-quant 口径下不需要

## A4：多主题交替流——**多域共存无切换成本（混合压倒性优势）**

### 设计

两个不相交主题池（A/B 关键词互斥）构造 ABABAB... 交替流，各 75 批 × 60 步
= 总 9000 步。测：主题切换成本、双域累积增益、源域遗忘、跨域干扰。

### 结果

| 指标 | h2e4（终端默认） | 纯 PCN 90M |
|---|---|---|
| **全程在线增益** | **+82.4%** | +53.7% |
| A 域增益 | +82.5% | +49.9% |
| B 域增益 | +82.2% | +57.5% |
| **切换成本（A 域 / B 域）** | **0.0% / 0.0%** | 0.0% / 0.0% |
| 终末 A 探针增益 | **+79.8%** | **-6.1%（负！）** |
| 终末 B 探针增益 | +79.4% | +43.2% |
| 终末源域恶化 | +1093%（≈12×） | +4426%（≈45×） |

### 四条发现

1. **多域共存无切换成本**：两架构的切换成本均为 0%——ABAB 交替流中，
   主题 A 批紧跟 B 批的在线 PPL 与 A 连续批无差异。**交替学习不比连续
   学习贵**。

2. **混合架构双域均衡（A 82.5% / B 82.2%），纯 PCN 严重偏斜（A 50% /
   B 57.5%，且 A 域探针终末转负 -6.1%）**——纯 PCN 在多域流中出现了
   跨域干扰：B 域的持续学习侵蚀了 A 域已获取的知识（A 探针在批 110 后
   跌入负值）。**混合架构的冻结主干保护了已学知识不被新域覆写**——这是
   主干锚定在多域共存场景的直接证据。

3. **源域遗忘差异（12× vs 45×）**：与单主题长程流（14× vs 47×）几乎
   一致——多域交替不加剧源域遗忘，遗忘量由总步数决定（9000 步不变）。

4. **部署含义**：终端多用户/多主题共存场景下，混合架构是唯一可行选择——
   纯 PCN 会「学了新的忘了旧的」，混合架构双域均衡且无额外成本。

### 与长程流（单主题）的对照

| | 单主题 150 批 | **交替 150 批（ABAB）** |
|---|---|---|
| h2e4 全程增益 | +84.9% | +82.4%（-2.5pp，近似） |
| h2e4 源域恶化 | 14× | 12× |
| PCN 全程增益 | +57.1% | +53.7% |
| PCN 源域恶化 | 47× | 45× |

交替流的增益略低于单主题流（-2~3pp）——两域共享参数预算的轻微竞争，
但代价极小。
