# 100M 规模验证：PCN vs Transformer（启智 V100 实测）

> 日期：2026-09-16 | 平台：启智社区 V100S-32GB | 目的：审稿人要求的规模验证数据点
> 实验脚本：run_openi.py v3.1 | 训练脚本：train.py（含 NaN 恢复机制）

## 一、实验设置（除架构外全部对齐）

| 项 | PCN (no_gating) | Transformer (SDPA) |
|---|---|---|
| 层数 / 宽度 | 24L / d=512 | 24L / d=512 |
| FFN | 2048 | 2048 |
| **参数量** | **90.48M** | **101.52M** |
| lr（各自扫描出的最优） | 1e-4 | 1e-3 |
| warmup / grad_clip | 2000 / 0.5 | 2000 / 1.0 |
| batch / seq / steps | 32eff / 256 / 10000 | 32eff / 256 / 10000 |
| tokens 总量 | 81.92M | 81.92M |

| 数据 | WikiText-103, GPT-2 BPE | 同左 |
| n_heads | 4 (d_head=128) | 4 (d_head=128) |

| PPL 优势 | **-40.1%**（基线 TF） | — |
| 收敛速度 | 35.9 min @ 4.7 steps/s | 30.9 min @ 5.4 steps/s |
| 吞吐 | ~38.5K tok/s | ~44.2K tok/s |

- **PCN 用少 10.9% 的参数，PPL 低 40.1%**（TF PPL 比 PCN 高 67%）
- PCN 两次运行差 0.16%（150.13 vs 150.37，同 seed=0，非确定性来源），运行间方差极小

## 四、与 2D 不对称定律的一致性

- 本实验点：~900 tokens/param，处于参数轴倒 U 型峰区（此前小规模峰位 ~1000 tok/param，+60.8%）
- 本次实测：+40.1%。方向与峰位一致，幅度略低——注意此前数据是 5-seed 小模型（12L/63M 以下），本次是 24L/90-100M 单点（PCN 2 次），PPL 区间也不同，属合理量级
- **结论：小规模规律在 10× 规模上成立，未消失、未反转**

## 五、数据效率外推（估算，标注：非实测）

用 TF 末段两点（65.9M→82M tokens，PPL 266.7→250.85）拟合幂律 a≈0.28，
TF 追平 PCN 150.25 需约 **6.2× tokens（~508M，~62k steps，~3.2h V100）**。
与数据缩减轴「低数据区优势最大」的结论互相印证。

## 六、诚实性声明（局限）

1. TF 为单 seed；PCN 两次运行显示该规模方差 ~0.16%，预计影响很小但未对 TF 做 5-seed
2. TF lr=1e-3 沿用 63M 规模扫描最优，未在 101M 重扫（可选：3 点扫描再花 ~15 积分）
3. n_heads=4/d_head=128 非常规配置，但两架构一致，对比公平；对 TF 绝对性能或有少量影响
4. PCN 峰值 VRAM 待从启智输出下载 results.json 核对后补入

## 七、附：本次踩坑记录（run_openi.py v3.1 修复）

- 现象：任务参数填 `mode = tf` 但实际重跑了一遍 PCN（PPL 150.37 ≠ 首次 150.13）
- 根因实证：v3.1 启动打印 `sys.argv = ['run_openi.py', '--mode=tf']`——**启智以等号形式传参**，
  旧解析 `arg == '--mode'` 精确匹配失败后静默回退默认 'pcn'
- 修复：去横线 + 等号兼容解析、默认改 tf、未知值硬退出、启动打印 argv
- 代价：~5 积分；副产品：PCN 同配置重复运行（150.13/150.37）成为运行间方差数据点
